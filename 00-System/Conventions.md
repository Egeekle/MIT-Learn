# Conventions

Single source of truth for note format and vocabulary. Templates in `Templates/` implement this file; change this file first, then the templates (see [[Architecture]], architecture gate).

## Frontmatter schema (knowledge notes)

| Field | Values | Notes |
|---|---|---|
| `type` | concept, formula, derivation, exercise, question, attempt, error, paper, experiment, dataset, project, source, review-card, diagnostic, session, course-unit | matches the template name |
| `status` | `draft` → `review` → `approved` | only the user promotes to `approved` |
| `version` | integer, starts at 1 | incremented on each change to an approved note |
| `source_type` | `mit`, `primary-research`, `secondary`, `generated`, `user` | see labels below |
| `sources` | list of `[[source-record]]` links or `UNVERIFIED` | never invented |
| `course` | e.g. `18.6501x` | optional outside course notes |
| `created`, `updated` | `YYYY-MM-DD` | |
| `tags` | list | |

The schema is additive: extra fields are allowed, existing fields are not renamed without an architecture change.

Exceptions to the `status` flow: `error` notes use `open` → `understood` → `resolved` (learner-state, not canon); `session`, `review-card` and `source` notes may omit `version`; a `session` with unanswered questions uses `status: awaiting-user`. Templates leave `{{date}}` / `{{title}}` placeholders for the creator to fill.

**Fixtures:** test or synthetic notes carry `fixture: true` (and tag `arch-test`). They are never approved, and `diagnostic`, `review` queues and `memory.md` counts ignore them.

## Source-type labels

- `mit`: MIT Learn / MITx course material (lectures, problem sets, readings the course provides).
- `primary-research`: a paper or original source by the researchers themselves.
- `secondary`: textbooks, blogs, lecture notes by others, explanations.
- `generated`: exercises, examples or explanations written by Claude. Never presented as MIT or research content.
- `user`: the user's own notes, photos, PDFs, derivations.

A note mixing types lists them per section, not in one blanket label.

## Integrity rules (short form; details in `.claude/rules/`)

- Never fabricate papers, citations, URLs, datasets, MIT resources or course material. If unsure, write `UNVERIFIED` and say what would verify it.
- Never silently fill in missing mathematical steps from user material. Use an uncertainty callout:

  ```
  > [!uncertain] Step missing in source
  > Going from line 3 to line 4 requires <what>. Not in the source; proposed bridge below is generated.
  ```
- Ambiguous handwriting/OCR: transcribe as read, mark `[?]` at the doubtful token, list doubts in the source record.

## Canonical workflow (DRAFT → REVIEW → APPROVED)

1. Claude writes or edits notes as `draft`.
2. When ready for the user, set `review` and say what needs checking.
3. Only the user's explicit approval sets `approved`.
4. Changing an `approved` note: copy the current file to `99-Archive/versions/<note-name>@v<N>.md`, bump `version`, add a line to the note's `## Version history` section, set `status: review`. Notes are not in git (see Repo scope), so `99-Archive/versions/` is the only version history; back up the vault yourself.

## Naming and layout

- Folders are numbered (`00`–`99`) so the vault order is stable; see [[Architecture]] for the map.
- Note names: `Title Case Or kebab-case` per folder convention: concepts use the concept name (`Fisher Information.md`); exercises `EX-<course>-<unit>-<nnn>.md`; errors `ERR-YYYY-MM-DD-<slug>.md`; source records `SRC-<slug>.md`; experiments `EXP-<slug>.md` (in `60-Experiments/<name>/`); diagnostics `DIAG-YYYY-MM-DD-<slug>.md`; paper notes `<Author> <Year> <Short title>.md`; formulas `FRM-<slug>.md` (in `20-Concepts/formulas/`); questions `QST-<slug>.md` (in `40-Exercises/questions/`); sessions `SES-YYYY-MM-DD-<slug>.md`.
- Links: wikilinks `[[Note]]` between notes; relative Markdown links for files outside notes.
- Math: `$inline$` and `$$block$$` (Obsidian/MathJax).

## Spaced review (plain Markdown)

- A review item is a `review-card` note or a `## Recall` block inside a concept, with frontmatter `next_review` (YYYY-MM-DD), `interval` (days), `ease` (default 2.5).
- `80-Learning/Reviews/queue.md` is regenerated by `/review` from those fields. Dataview is optional, not required.
- Grading update rule is defined in `.claude/skills/review/SKILL.md`, not duplicated here.

## Error tracking

One note per error in `80-Learning/Errors/`. Type taxonomy: `conceptual`, `algebraic`, `notation`, `interpretation`, `computational`, `misread-problem`, `recall`. Each error links to the concept it exposes; `/diagnose` aggregates them.

## Repo scope

The GitHub remote is public and holds **only the system architecture**: `CLAUDE.md`, `README.md`, `.claude/`, `00-System/` (including Templates and `memory.md`) and the empty folder skeleton (`.gitkeep`). PDFs, images, course exports, datasets and all learning notes (folders `01`–`99`) stay on the user's computer and are git-ignored. Never paste large verbatim MIT material into notes; paraphrase and cite the location (unit/page/timestamp). Claude never changes repo visibility, never force-adds ignored content, and never commits or pushes without explicit user approval. `memory.md` is tracked and therefore public: keep it to non-sensitive state.
